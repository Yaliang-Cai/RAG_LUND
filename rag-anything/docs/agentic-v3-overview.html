Agentic RAG v3

LLM-driven retrieval agent · built on RAG-Anything + LightRAG

Replaces the fixed retrieval pipeline with a real agent loop: the model decides which tool to call, with what query and budget, accumulates evidence across steps, self-grades coverage, and answers only when the evidence supports it — with a hard cost/time budget and per-turn session memory for multi-turn conversations.

How one turn works

Planrewrite + classify
→
Decidepick tool + params
→
Retrieveinto evidence pool
→
Gradefact ledger / coverage
→
Answer+ cite check
↺ insufficient evidence → loop back (cheap → escalate), bounded by cost-points · 60 s · token guardrails

Minimal retrieval toolset — one clear choice per step

search
LightRAG local + global knowledge graph fused with hybrid (dense + BM25) chunk vectors, reranked at admission. The default for facts, entities, definitions, summaries.
search_multihop
Personalized PageRank over the entity graph for bridge / comparison / causal / cross-document reasoning. No rerank — PPR already ranks by multi-hop relevance.
answer
Finish and generate from gathered evidence (direct · map-reduce · CoT-reflect).

Why it is better

  • Evidence accumulates across steps; reranking is incremental (no repeated work).
  • Fact ledger drives coverage and targeted re-retrieval; abandons unverifiable details instead of looping.
  • Grounding by citation — claims are checked verbatim against sources by code, not self-judged.
  • Budget-aware: cost-points + wall-clock + token guardrails; fast-path for simple questions.
  • Session memory: coreference resolution + cross-turn evidence cache.
  • Answers in the user's language; full chain trace per turn in Phoenix.

Stack

Qwen3-VL-30B (vLLM) · Neo4j · Qdrant (dense + BM25) · PostgreSQL governance · role-separated model pool (pluggable small judge) · React UI · Arize Phoenix tracing.
